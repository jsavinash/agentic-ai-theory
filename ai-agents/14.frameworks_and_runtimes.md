# AI Agents: Comprehensive Guide to Frameworks and Runtimes

## 1. Core Definition

**Frameworks and runtimes** are the foundational software stack that translates abstract cognitive concepts into executable code. While principles like memory, self-reflection, and output validation define *how* an agent should behave, this layer provides the concrete engineering scaffolding — state machines, async task queues, event loops, persistence, and SDK bindings — needed to run autonomous systems reliably at enterprise scale.

---

## 2. Framework vs. Runtime: The Technical Divide

Production agent engineering clearly delineates design-time abstractions from run-time execution spaces:

| Architectural Layer | Primary Responsibility | Core Engineering Scope | Production Examples |
| :--- | :--- | :--- | :--- |
| **Framework / SDK** | **Design & Abstraction:** declare agent personas, register typed tools, structure memory routers, map prompt graphs | Building the blueprint and compiling application logic | LangGraph, OpenAI Agents SDK, Google ADK, Microsoft Agent Framework, CrewAI |
| **Runtime Environment** | **Lifecycle & Execution:** state persistence, async compute fabrics, event-loop scaling, isolation boundaries | Hosting the live agent process and preserving stability | Temporal, LangGraph Platform (Agent Server), cloud agent runtimes (AWS Bedrock AgentCore, Azure AI Foundry Agent Service, Google Vertex AI Agent Engine) |

*Note on naming:* "runtime" is used loosely in marketing; in this series a **runtime** owns *durable state and scheduling* (Parts 3 & 5), while a **framework** owns *graph structure and prompts*. Many platforms sell both — LangGraph (framework) + LangGraph Platform (runtime) is the canonical split.

## 3. Framework Typologies

Modern frameworks structure agent coordination around distinct architectural models:

### A. Graph-Based State Machines (Deterministic Orchestration)

*   **Champions:** LangGraph, LlamaIndex Workflows
*   **Mechanics:** the pipeline is a state chart — nodes are LLM calls or tool actions; edges are routing conditions. Checkpointer + store give durable threads and long-term memory (Part 3, §5).
*   **Optimal use:** mission-critical pipelines (financial processing, support routing) requiring predictable paths, HITL interrupts, and strict guardrails.

### B. Conversation-Native Actor Networks

*   **Champions:** Microsoft Agent Framework (successor to AutoGen + Semantic Kernel), CrewAI
*   **Mechanics:** agents are actors exchanging structured messages; orchestration emerges from conversation patterns — handoffs, delegations, group chats.
*   **Optimal use:** exploratory, emergent collaboration — research, multi-role software engineering.

### C. Minimal-Primitive SDKs

*   **Champions:** OpenAI Agents SDK
*   **Mechanics:** a deliberately tiny vocabulary — **Agents, Handoffs, Guardrails, Sessions, Tracing** — with Python control flow as the orchestration language.
*   **Optimal use:** teams that want agent ergonomics without adopting a graph framework.

### D. Declarative Agent Trees

*   **Champions:** Google ADK
*   **Mechanics:** composable primitives — `SequentialAgent`, `ParallelAgent`, `LoopAgent`, `CoordinatorAgent` — with `session.state` as the shared whiteboard and native **A2A** support (Part 1, §3; Part 2, §2).
*   **Optimal use:** explicit composition of the canonical patterns from Part 2, deployed on Google Cloud.

> **⚠️ 2026 landscape note:** the separate **AutoGen** and **Semantic Kernel** SDKs were consolidated into the **Microsoft Agent Framework** (v1.0 GA, April 2026, Python + .NET parity, A2A/MCP interop). Treat AutoGen as maintenance-mode; new projects target Agent Framework (Parts 1 & 5, §5).

### 3.1 Framework Comparison Matrix

| Framework | Orchestration Model | Key Primitives | Protocols | Best For |
| :--- | :--- | :--- | :--- | :--- |
| **LangGraph** | Cyclic state graphs | Nodes, edges, checkpointers, `BaseStore`, interrupts | MCP (via adapters) | Custom, durable, auditable workflows |
| **OpenAI Agents SDK** | Handoff/manager loops | Agents, handoffs, guardrails, sessions, tracing | MCP servers | Lightweight delegation chains |
| **Google ADK** | Declarative agent trees | Workflow agents, `session.state`, A2A integration | A2A native, MCP | Pattern-composed teams on GCP |
| **Microsoft Agent Framework** | Orchestrations + conversations | Agents, orchestrations (sequential/concurrent), A2A/MCP client | A2A + MCP | Enterprise .NET/Python standardization |
| **CrewAI** | Role-based crews | Agents, tasks, crews, flows, memory | Tool integrations | Persona-driven rapid prototyping |

## 4. The Production Runtime Infrastructure Stack

```text
 ┌────────────────────────────────────────────────────────┐
 │                   APPLICATION CODE                     │
 │      Agent Personas, Tool Registers, Prompt Schemas    │
 └──────────────────────────┬─────────────────────────────┘
                            ▼
 ┌────────────────────────────────────────────────────────┐
 │                   FRAMEWORK ENGINE                     │
 │   Graph Compilation, Schema Hinting, Context Routing   │
 └──────────────────────────┬─────────────────────────────┘
                            ▼
 ┌────────────────────────────────────────────────────────┐
 │                   RUNTIME SERVICES                     │
 │   Durable Execution, Async Queues, Telemetry Tracing   │
 └──────────────────────────┬─────────────────────────────┘
                            ▼
 ┌────────────────────────────────────────────────────────┐
 │                   COMPUTE SANDBOX                      │
 │    Docker/gVisor Isolation, Ephemeral File Systems     │
 └────────────────────────────────────────────────────────┘
```

*   **Durable Execution & State Serialization:** when an agent parks at a HITL gate for days, the runtime serializes memory, tokens, and step positions to a persistent store; approval rehydrates it without repeating completed nodes (Parts 3 & 9).
*   **Isolated Compute Sandboxing:** generated code and untrusted tools execute in ephemeral containers with egress allowlists — prompt injections never reach host storage or kernels (Part 7, §6.1).
*   **Observability (OpenTelemetry):** structured spans — token consumption, tool latency, cost, and full prompt histories — flow to tracing backends (LangSmith, Phoenix, OTel collectors). If you cannot replay a decision trace, you cannot debug an agent (Part 3, §3B).

## 5. Choosing a Stack: Decision Heuristics

1.  **Start with the least framework you can tolerate.** Many production agents need only an SDK (Agents SDK, ADK) plus a queue — not a graph database.
2.  **Graph when state must be durable and auditable.** Long-running, regulated, or interruptible workflows justify LangGraph/Temporal-class machinery.
3.  **Check the protocol surface first.** If you must interoperate with third-party agents, prefer runtimes with first-class **A2A** support; for tool ecosystems, **MCP** connectivity is the baseline (Part 1, §3.1).
4.  **Hosted vs. self-managed is an ops decision, not a feature decision.** Managed runtimes (LangGraph Platform, cloud agent runtimes) trade lock-in for eliminating the persistence/scale problem entirely.
5.  **Verify with benchmarks, not demos.** Whatever the framework, measured reliability lives in Part 12's benchmark gap — budget evaluation (Part 13, §6) into the choice.
