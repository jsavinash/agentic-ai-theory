# Intent Preservation in Agentic AI: Technical Architecture

This document explains the concepts, failure modes, and engineering frameworks used to achieve **Intent Preservation** — keeping autonomous multi-agent systems aligned with the user's original objective across long-horizon execution.

---

## 1. What is Intent Preservation?

**Intent Preservation** is the mechanism that ensures an AI system remains strictly aligned with the user's original **objective, constraints, and success criteria** throughout a long, multi-step execution loop.

When a human issues a complex, high-level prompt, the agent decomposes it into dozens of sub-tasks, tool calls, and handoffs. Without deliberate preservation, systems suffer **Intent Drift** — later iterations or sub-agents lose sight of the overarching goal, producing hallucinations, safety violations, or incomplete execution.

```text
[ Human Prompt ] ───> [ Core Intent Anchor ] ───> [ Sub-Task 1 ] ───> Success ✅
                             │
                             └───────────────────> [ Sub-Task 2 ] ───> Success ✅
                             │
                             └───────────────────> [ Sub-Task 3 ] ───> Success ✅
```

**Why this matters empirically:** on **UserBench** (Salesforce, 2025) — where simulated users reveal preferences incrementally — leading models fully aligned with *all* user intents only **~20% of the time**, and surfaced fewer than **30%** of available preferences through active clarification. Task completion and intent alignment are measurably different things.

---

## 2. The Mechanics of Intent Drift

Intent drift occurs across three primary architectural vectors:

- **Token Dilution:** As tool outputs, error logs, and retrieved documents flood the context window, the original objective is pushed out of active attention or buried under noise.
- **Handoff Degradation:** In multi-agent systems (Planner → Executor), instructions are *summarized* at each boundary. Like a game of telephone, precise nuances and constraints are lost across handoffs.
- **State Space Explosion:** During self-correction loops, the agent optimizes *locally* to fix an immediate bug while silently abandoning global business constraints (e.g., "read-only" or "never email customers").

---

## 3. Engineering Strategies for Intent Preservation

### A. Intent Anchoring (Global Context Invariant)

Rather than passing the original prompt sequentially through the loop, frameworks hold it in a dedicated, **read-only memory register** — the **Intent Anchor**.

- The original user prompt, immutable safety constraints, and success criteria are injected as a **system-level invariant** on every model call.
- Every sub-agent and tool payload programmatically binds to this anchor, so its attention weight never decays as context grows.

### B. Dual-Loop Architecture (Planner vs. Executor)

Separating reasoning from execution prevents local tool errors from polluting global strategy:

- **Outer loop (Planner):** owns the Intent Anchor; reviews system state after each tool call and judges whether progress still matches global goals.
- **Inner loop (Executor):** short-lived and stateless; executes exactly one micro-task (write a SQL query, call an API) and **cannot** mutate the global plan.

### C. Programmatic Evaluation & Guardrails

Deterministic verification code — not the LLM policing itself — enforces alignment:

- **Structured output enforcement:** JSON Schema / Pydantic validation rejects malformed or semantically drifted responses before they advance the state machine.
- **LLM-as-a-Judge verification:** a decoupled model instance scores the final state against the Intent Anchor using an explicit binary checklist (`goal_achieved: true|false`), with an independent judge model to reduce self-preference bias.

### D. Context Compaction with Constraint Pinning

When context is summarized to control cost, **never** summarize away the anchor: compaction applies only to conversational history, while constraints, success criteria, and the last N tool results are re-injected verbatim on every turn.

## 4. Architectural Implementation Example

```python
from typing import List
from pydantic import BaseModel


class IntentAnchor(BaseModel):
    """Immutable invariant: injected into every model call, never summarised."""
    original_goal: str
    immutable_constraints: List[str]
    success_criteria: List[str]


class AgentState(BaseModel):
    intent: IntentAnchor                       # read-only global invariant
    current_step: int = 0
    execution_logs: List[str] = []
    is_aligned: bool = True                   # re-evaluated by outer loop each step


def evaluate_step_alignment(state: AgentState, latest_output: str, judge) -> bool:
    """Outer-loop verifier run after every tool execution.

    Deterministic constraint checks run first (cheap, exact); the
    decoupled LLM-as-a-Judge handles semantic criteria second.
    """
    for constraint in state.intent.immutable_constraints:
        if constraint.lower() in latest_output.lower():   # e.g. forbidden "DROP TABLE"
            state.is_aligned = False
            return False

    verdict = judge(
        objective=state.intent.original_goal,
        criteria=state.intent.success_criteria,
        candidate_output=latest_output,
    )
    state.is_aligned = verdict.goal_achieved
    return state.is_aligned
```

## 5. Architectural Summary

Intent preservation turns AI from a reactive text generator into a reliable enterprise worker. **Anchor the original prompt globally**, isolate execution loops from strategic reasoning, compact context without dropping constraints, and audit every handoff programmatically — and long-duration autonomous operations complete without wandering off-course.
