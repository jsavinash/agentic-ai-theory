# Agentic AI & Open Agent Protocols: Technical Overview

This document explains the core architecture of **Agentic AI** and the open interoperability standards that govern it — **AGENTS.md**, **AG-UI**, **MCP**, and **A2A** — most of which are now hosted by the **Agentic AI Foundation (AAIF)** under the **Linux Foundation**.

---

## 1. Understanding Agentic AI

Unlike traditional "static" AI systems that act purely as text predictors, **Agentic AI** refers to software systems with **autonomy, persistent state, and tool execution**. An agent completes open-ended workflows via an iterative control loop:

```text
       ┌───────────┐      ┌─────────────┐
  ───> │  Observe  │ ───> │ Plan/Reason │ ───┐
       └───────────┘      └─────────────┘    │
             ▲                             ▼
             │       ┌───────────┐   ┌─────────────┐
             └────── │  Reflect  │ <─│   Execute   │
                     └───────────┘   └─────────────┘
```

1. **Observe:** Consume environment context, user intent, tool results, or system state.
2. **Plan & Reason:** Decompose a high-level goal into a dependency-ordered task graph.
3. **Execute:** Invoke tools, call APIs, or write and run code to change state.
4. **Reflect:** Grade the result against success criteria; loop, replan, or escalate.

**Key differentiator:** the model decides *which* actions to take and *when* to stop — which is precisely why open protocols, guardrails, and observability (the rest of this series) are mandatory. The canonical research anchor is the **ReAct** pattern (Yao et al., 2022); production frameworks such as **LangGraph**, **OpenAI Agents SDK**, **Google ADK**, **CrewAI**, and the **Claude Agent SDK** implement variants of this loop.

## 2. The 4 Layers of Agent Protocols

To prevent the ecosystem from fracturing into vendor-locked silos, the industry standardized **agent protocols** across four interaction layers:

| Layer | Protocol | Origin / Governance | Purpose |
| :--- | :--- | :--- | :--- |
| **Agent ↔ Context** | **`AGENTS.md`** | AAIF (Linux Foundation) | Repo-level markdown instruction manual for AI coding agents. |
| **Agent ↔ User** | **`AG-UI`** | Open source (originated at CopilotKit) | Event-based protocol linking agent runtimes to user-facing frontends. |
| **Agent ↔ Tools & Data** | **`MCP`** | Anthropic-originated; AAIF-hosted | Standardized discovery and invocation of tools, data, and resources. |
| **Agent ↔ Agent** | **`A2A`** | Google-originated; AAIF-hosted | Multi-agent task delegation across organizational boundaries. |

**AAIF in brief:** launched in 2025 under the Linux Foundation, it hosts **MCP, A2A, AGENTS.md, goose, and agentgateway**, with a governing board spanning AWS, Google, Microsoft, OpenAI, Anthropic, Cloudflare, Bloomberg, Block, and Shopify.

## 3. Deep Dive: Key Protocols Explained

### A. MCP (Agent ↔ Tools & Data)

**Model Context Protocol** standardizes how agents connect to external systems. Every integration is a *server* exposing **tools**, **resources**, and **prompts** over JSON-RPC.

- **Spec cadence:** `2025-03-26` → `2025-06-18` → `2025-11-25` → **`2026-07-28` (current)**.
- **Transports:** `stdio` (local processes) and **Streamable HTTP** (remote servers); the older HTTP+SSE transport is formally deprecated.
- **Security:** OAuth 2.1 with resource indicators for remote servers; tool annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`) let clients warn before destructive calls.
- **2026-07-28 changes:** MCP is now **stateless** — the `initialize` handshake is gone, each request carries capability metadata in `_meta`, and servers MUST implement **`server/discover`** for version negotiation. Server-push was consolidated into `subscriptions/listen` plus a **Multi Round-Trip Requests (MRTR)** pattern; long-running jobs moved to the `tasks` extension; **roots, sampling, and logging are deprecated** under a new 12-month feature lifecycle policy.
- **Ecosystem:** the official **MCP Registry** (`registry.modelcontextprotocol.io`) provides verified server discovery.

### B. A2A (Agent ↔ Agent Coordination)

The **Agent2Agent Protocol** lets a client agent delegate sub-tasks to remote agents without knowing their internals.

```text
[ Client Agent ] ──(Discovery/Auth)──> [ A2A Server Agent ] ──> [ Processes Sub-Task ]
```

- **Agent Card:** a JSON document served at `/.well-known/agent-card.json` advertising skills, endpoints, and auth schemes — as of **v1.0**, cards carry **cryptographic signatures** (RFC 7515 JWS over RFC 8785 canonicalization) for verifiable identity.
- **Task lifecycle:** stateful tasks move `submitted → working → input-required | completed | failed | canceled`, with SSE streaming updates and **push notifications** (webhooks) for long-running work.
- **v1.0 (2026) highlights:** multi-tenancy, per-interface **protocol-version negotiation**, standardized `google.rpc.Status` errors, and authenticated *extended cards*.
- **IP protection:** coordination happens through messages and artifacts — an agent on one cloud can task an on-prem agent without exposing proprietary prompts or internal databases.

### C. AG-UI (Agent ↔ User Interaction)

**AG-UI** streams agent execution into frontends as a typed **event protocol**: text deltas, state diffs, actions, tool events, and reasoning steps.

- **Bi-directional:** the frontend can send interrupts and approvals back — the standard mechanism for **human-in-the-loop (HITL)** confirmation (approving a payment, merging a PR).
- **Generative UI:** agents emit structured components instead of raw text. Note that Google's **A2UI** is a *separate* declarative generative-UI specification that complements AG-UI.
- **Framework support:** first-party integrations ship for LangGraph, CrewAI, Google ADK, Microsoft Agent Framework, and direct-to-LLM apps (TypeScript, Python, .NET SDKs).

### D. AGENTS.md (Agent ↔ Context)

A flat markdown file at the repo root that gives coding agents project conventions *before* generation starts.

- **Replaces:** tool-specific dotfiles (`.cursorrules`, ad-hoc system prompts) that caused context pollution and token waste.
- **Hierarchy:** nested `AGENTS.md` files cascade — user-global → repo root → subdirectory, with deeper files overriding shallower ones for localized constraints.
- **Adopted by:** OpenAI Codex and a growing roster of coding agents (Cursor, GitHub Copilot, Google Jules, and others), dramatically reducing wall-clock time and code-diff churn.

---

## 4. Architectural Summary

Combining all four layers yields composable agent infrastructure: an enterprise system follows **`AGENTS.md`** conventions, streams progress to end users via **`AG-UI`**, reaches databases and terminal runtimes through **`MCP` servers**, and delegates parallel jobs across distributed networks via **`A2A` routing**.
